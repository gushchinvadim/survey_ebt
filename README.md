# Обновление LOSA

## Порядок установки
1. Сделайте резервную копию БД (для SQLite остановите сервер и скопируйте db.sqlite3).
2. Пока старый models.py ещё содержит AuditRating, скопируйте ТОЛЬКО management/commands/migrate_legacy_ratings.py в приложение losa.
3. Выполните `python manage.py migrate_legacy_ratings`. Команда переносит старые оценки, заполняет пустые значения новой таблицы, при конфликте отменяет весь перенос. Если таблица новой модели ещё не создана, сначала примените ранее подготовленную миграцию её создания.
4. После успешного переноса замените models.py, admin.py и serializers.py приложенными версиями.
5. Удалите временную команду migrate_legacy_ratings.py. В новом models.py модели AuditRating уже нет.
6. Уберите старый импорт initialize_assessments из других частей проекта, если он там есть. Старый services.py с этой функцией больше не используется: удалите его только если в нём нет другого нужного кода. Команду seed_assessment можно оставить — она использует сохранённые справочники.
7. Выполните `python manage.py check`, затем `python manage.py makemigrations losa`.
8. Проверьте миграцию: удаляется только устаревшая модель AuditRating. AuditAssessment остаётся для изложения фактов, AssessmentTemplate/Section/Criterion/Stage сохраняются. Затем `python manage.py migrate`.

Старые миграции не удалять. Если перенос не прошёл, не применяйте удаление AuditRating.

## Что изменилось
- Одна схема оценок: AuditCriterionRating напрямую связан с листом и этапом.
- AuditAssessment сохранён как изложение фактов по этапу: данные не удаляются.
- В листе доступны inline ошибок, угроз, оценок, фактов и стабилизированного захода.
- Убраны устаревшие вложенные оценки и initialize_assessments.
- Шаблоны, разделы, критерии, факты и оценки редактируются с обычными правами Django.
- Существующие коды, обязательность полей, связи и имена таблиц сохранены.
- Excel-загрузка использует существующую команду load_exel и существующие HTML-шаблоны. Они не требуют замены и не включены в пакет.

## API
Все актуальные модели имеют сериалайзеры. Лист возвращает вложенные события, оценки, факты и стабилизированный заход. Вложенные списки только для чтения; записи создаются/изменяются отдельными сериалайзерами. Единая офлайн-загрузка, views, маршруты и права API в этом обновлении не реализованы.
Не направляйте вложенные списки в POST листа: пока сохраняйте их отдельно.
ФИО аудитора выдаётся; Pilot содержит номера сотрудников без ФИО. Это служебное API, а не обезличенный аналитический отчёт.
Шаблон листа фиксируется в админке после появления оценок; сами оценки всегда редактируемы. Межтабличное совпадение шаблона и критерия пока не ограничено — выбирайте критерии соответствующего шаблона.
